ALGORITHM EXPLANATION

從 Dense 儲存走到 CSR 運算

教學動畫，非時脈精確 RTL 波形

A：原始矩陣

列 row、欄 column 從 0 開始。淡色格是零。

B：保持 Dense

A[r,k] 配對 B[k,c]。B 即使為零，這筆仍是必要排程。

C：累加後寫回

未寫回顯示「·」。空列也要寫出四個零。

values：非零值

只存 A 的非零數值，保留正負號。

col_idx：原欄號

每個 value 原本在 A 的哪一欄，也決定 B 的列 k。

row_ptr：列範圍

第 r 列的位置是 [row_ptr[r], row_ptr[r+1])；起點等於終點代表空列。

這個動畫與實際硬體有什麼差別？

動畫把 CSR 建表也畫出來，方便理解；本專案 CSR 引擎的資料由載入介面提供，沒有宣稱板上會自動把 Dense A 壓成 CSR。動畫每一步不是 FPGA 一拍。實際 FSM 還有 CHECK、SEED、FETCH、ISSUE、DRAIN、WRITE；下一頁可看真正 ModelSim 取樣。

這個教學案例的實際 RTL busy count：Dense 178 拍、CSR 90 拍。不包含資料載入、壓縮與 PC 傳輸；75% 的 MAC 減少不等於 75% 的執行時間或功耗改善。

同一組 LED，兩版 Top 的意義不同

最早 ROM Demo

KEY0 Reset；KEY1 Start；SW[1:0] 選四種矩陣。LED0 Busy、LED1 Done、LED2 板內比較 PASS、LED3 Fail。

當時由板主人工回報：Reset 後全滅，完成後 LED1、LED2 亮。這是文字觀察，沒有冒充實拍影片。

後來 A14 可讀回版本

PC 經 JTAG 載入／啟動；KEY1 不啟動。LED0 Busy、LED1 response-ready、LED2 兩引擎結果可讀、LED3 error。

板主回報 Reset 後 LED1 亮，完成後 LED1、LED2 亮。LED2 本身不證明算對，正確性由完整讀回支持。

功耗與時序限制也保留

RAM read-enable 候選在指定 Power Analyzer 條件下，核心動態功耗估計降低 10.02%–11.30%，總 FPGA 估計只低約 0.075%–0.084%。比較的是同一引擎原版／候選版，不是直接 CSR 對 Dense。

沒有量測實板瓦數。外部 JTAG 正式時序 signoff 仍 BLOCKED；內部已約束路徑通過與指定案例算對，不取代完整 signoff。失敗的傳輸紀錄亦保留在研究庫中。
